## Сайт (`web/`)

Next.js 16 + PostgreSQL (Neon). Весь сайт открыт только после входа; индексация запрещена.

```bash
cd web
cp .env.example .env.local   # задать логин, пароль и SESSION_SECRET
npm install
npm run dev                  # http://localhost:3000
```

Проверки перед отправкой: `npm run build && npx tsc --noEmit` (сборка сама сначала запускает линтер и тесты). Render собирает сайт той же командой, поэтому версия с упавшим тестом на сайт не попадёт. Дополнительно GitHub Actions (`.github/workflows/ci.yml`) на каждый PR и пуш в `main` проверяет миграции на чистой PostgreSQL. После загрузки источников там же идут браузерные проверки (`web/e2e/`, Playwright): вход, чтение, поиски, графы, закладки. Локально: `npm run e2e` на собранном сайте и базе с миграциями и источниками; если браузер Playwright не установлен — `npx playwright install chromium`.

### База данных

Таблицы лежат в двух схемах: `library` — тексты источников, `public` — всё, что делается в админке (`docs/DATA_MODEL.md`, «Две схемы»). Миграции — SQL-файлы в `db/migrations/` (`001_…sql`, `002_…sql`). Они накатываются по порядку при каждом запуске сайта (`npm start` вызывает `scripts/migrate.mjs`, затем загрузку источников); уже применённые записаны в таблице `_migrations`. Вручную: `cd web && npm run db:migrate`. Без `DATABASE_URL` миграции пропускаются.

Переменные на Render:

| Переменная | Что это |
| --- | --- |
| `DATABASE_URL` | Neon → проект `manba` → **Connect**, прямая строка (без «Connection pooling»). Запасная база Supabase подключается строкой **Session pooler** (порт 5432): прямой адрес `db.<ref>.supabase.co` Render не видит |
| `DATABASE_SSL` | `true` |

Правила:

- новая миграция — новый файл со следующим номером; применённые файлы не меняются;
- публичные роли Supabase (`anon`, `authenticated`) доступа к таблицам не имеют: данные идут только через наш сервер; каждая новая таблица закрывается вызовом `SELECT close_to_public('имя_таблицы');` (автопроверка следит за этим);
- новая таблица источников создаётся как `library.<имя>`, таблица данных админки — без схемы;
- журнал `change_log` и будущие опубликованные тексты защищены триггером `forbid_change()`: изменить или удалить запись нельзя, исправление — новой записью.

### Загрузка источников

Файлы источников лежат в `data/sources/` (Коран из Tanzil, сборники хадисов, сира, тафсир и другие книги из OpenITI, перевод Саблукова, тексты других религий). При запуске сайта после миграций `npm run db:import` загружает то, чего ещё нет в базе; повторный запуск ничего не меняет. Подробно — `docs/DATA_MODEL.md`.

### Вход

Весь сайт открыт только после входа. Главный администратор входит по логину и паролю из настроек сервера; остальные — учётные записи с ролью «администратор» или «читатель», которые заводятся в «Админка → Пользователи» с временным паролем (при первом входе задаётся свой).

Переменные окружения (на Render: сервис `manba` → Environment):

| Переменная | Что это |
| --- | --- |
| `SITE_LOGIN` | логин главного администратора |
| `SITE_PASSWORD` | его пароль; после смены он выходит из сайта на всех устройствах |
| `SESSION_SECRET` | случайная строка от 32 символов (`openssl rand -base64 32`) |

Если какой-то переменной нет, главный администратор войти не может. Неудачные попытки входа считаются в базе (`auth_failures`), после серии ошибок вход с этого адреса и для этого логина временно закрывается.
