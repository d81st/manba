## Сайт (`web/`)

Next.js 16 + PostgreSQL (Supabase). Весь сайт закрыт общим логином и паролем; индексация запрещена.

```bash
cd web
cp .env.example .env.local   # задать логин, пароль и SESSION_SECRET
npm install
npm run dev                  # http://localhost:3000
```

Проверки перед отправкой: `npm run build && npx tsc --noEmit` (сборка сама сначала запускает линтер и тесты). Render собирает сайт той же командой, поэтому версия с упавшим тестом на сайт не попадёт. Дополнительно GitHub Actions (`.github/workflows/ci.yml`) на каждый PR и пуш в `main` проверяет миграции на чистой PostgreSQL.

### База данных

Миграции — SQL-файлы в `db/migrations/` (`001_…sql`, `002_…sql`). Они накатываются по порядку при каждом запуске сайта (`npm start` вызывает `scripts/migrate.mjs`, затем загрузку источников); уже применённые записаны в таблице `_migrations`. Вручную: `cd web && npm run db:migrate`. Без `DATABASE_URL` миграции пропускаются.

Переменные на Render:

| Переменная | Что это |
| --- | --- |
| `DATABASE_URL` | Supabase → проект `manba` → **Connect** → **Session pooler** (порт 5432), с паролем базы. Прямой адрес `db.<ref>.supabase.co` Render не видит (только IPv6) |
| `DATABASE_SSL` | `true` |

Правила:

- новая миграция — новый файл со следующим номером; применённые файлы не меняются;
- публичные роли Supabase (`anon`, `authenticated`) доступа к таблицам не имеют: данные идут только через наш сервер; каждая новая таблица закрывается вызовом `SELECT close_to_public('имя_таблицы');` (автопроверка следит за этим);
- журнал `change_log` и будущие опубликованные тексты защищены триггером `forbid_change()`: изменить или удалить запись нельзя, исправление — новой записью.

### Загрузка источников

Файлы источников лежат в `data/sources/` (сейчас — текст и метаданные Корана из Tanzil). При запуске сайта после миграций `npm run db:import` загружает то, чего ещё нет в базе; повторный запуск ничего не меняет. Подробно — `docs/DATA_MODEL.md`.

### Вход на время разработки

Весь сайт закрыт одним общим логином и паролем. Почта и учётные записи пользователей появятся позже.

Переменные окружения (на Render: сервис `manba` → Environment):

| Переменная | Что это |
| --- | --- |
| `SITE_LOGIN` | логин |
| `SITE_PASSWORD` | пароль; после смены все выходят из сайта |
| `SESSION_SECRET` | случайная строка от 32 символов (`openssl rand -base64 32`) |

Если какой-то переменной нет, войти нельзя (сайт остаётся закрытым). После 10 неверных попыток с одного адреса вход закрывается на 15 минут.
