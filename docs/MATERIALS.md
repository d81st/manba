# Материалы автора: каталог

Архив (`materials/`) для будущей работы; закрыт, только когда репозиторий приватный (см. правило 7). Правила:

1. **Материал ≠ источник.** Пока материал не сверен с первоисточником, он не цитируется на сайте как факт. Утверждения из него — наводки для проверки (как очередь «Новые находки» в плане).
2. **Все стороны.** Критические, полемические и апологетические тексты одинаково нужны: они показывают, какие вопросы задают и как на них отвечают. На сайте каждое утверждение идёт со своим источником и степенью признания (традиция / большинство исследователей / гипотеза меньшинства), рядом — ответ другой стороны.
3. **Права.** У каждого файла записан статус прав. Публиковать текст или отрывки можно только после проверки лицензии; пересказ со ссылкой допустим.
4. **Материалы с призывами к насилию** (решение автора 18.10.2026) сохраняются как свидетельство того, что такое тоже есть, но на сайт не выводятся — ни сейчас, ни без отдельного решения автора и юридической проверки. На сайте можно разбирать, как такие тексты используют и как им возражают. Хранить их не в git, а в закрытом хранилище (приватный бакет Supabase Storage, когда он появится; до этого — у автора): правила GitHub запрещают такой контент даже в закрытых репозиториях, а хранение и передача в ряде стран (в том числе в Узбекистане) наказуемы. Канонические тексты (аяты, хадисы о войне) к таким материалам не относятся.
7. **Хранить вне публичного репозитория.** `d81st/manba` остаётся публичным (решение автора 18.10.2026: у закрытого репозитория ограничены бесплатные минуты GitHub Actions). Поэтому файлы материалов хранятся в отдельном закрытом месте (см. «Где хранить»), а здесь — только каталог. Уже лежащие в `materials/` файлы перенести туда и убрать отсюда.
5. Новые материалы добавляются сюда же: файл в `materials/<дата>/`, строка в таблицу ниже.
6. **Две половины монеты.** Автор присылает материалы в два захода: сначала критические, затем ответы традиции и защитников. У каждого материала отмечается сторона («критика» / «ответ традиции» / «исследование» / «нейтральный»). Тема попадает на сайт только тогда, когда для неё собраны обе половины: одну сторону без другой не публикуем. Список тем, по которым ещё нет ответа, — в разделе «Темы, ждущие второй половины» ниже.

### Утверждения из «Хушпара» для проверки

Это слова персонажей художественного текста, а не факты. Для каждого — найти первоисточники и исследования, показать позицию традиции и позицию критиков/исследователей со степенью признания:

1. Имя «Аллах» было известно доисламским арабам (имя отца пророка — Абдуллах).
2. Чёрный камень Каабы — метеорит, почитавшийся до ислама.
3. Аллат, аль-Узза и Манат — доисламские богини мекканцев (они названы в Коране, 53:19–20; подробно — у Ибн аль-Кальби).
4. Обход Каабы, лунный календарь и месяц Рамадан — доисламского происхождения.
5. Полумесяц как символ — доисламский.
6. Кто такие сабии из Корана (2:62) — толкования расходятся.
7. Битва при Бадре — персонаж отрицает её историчность; сопоставить традиционные источники (сира, хадисы) и позиции историков.

## Большие файлы

В git помещаются файлы до 100 МБ, через подключение к Google Drive читаются только файлы до 10 МБ. Большой RTF почти всегда большой из-за картинок (текст подборки на 22 МБ занимает 33 КБ). Варианты:

1. **Только текст:** открыть в Word → «Файл» → «Сохранить как» → «Обычный текст (*.txt)», кодировка Юникод (UTF-8) — и прислать в чат или положить на Google Drive.
2. **С картинками:** «Сохранить как» → «Документ Word (*.docx)» (картинки сжимаются). Если всё ещё больше 100 МБ — сохранить и TXT, и DOCX: текст разберём сразу, картинки — отдельно.
3. **Сжать в ZIP** и прислать в чат, если архив проходит.
4. **Достать картинки отдельно:** в Word «Сохранить как» → «Веб-страница (*.htm)» — рядом появится папка со всеми картинками файла; её можно сжать в ZIP.

Для постоянного хранения больших файлов — закрытый бакет Supabase Storage (можно сделать вместе с загрузкой материалов через админку).
