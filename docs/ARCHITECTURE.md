# Архитектура кода сайта

08.11.2026 · Решение автора: модули в духе Angular, по правилам Next.js. Пробный модуль — «Темы», затем по тому же образцу перенесены все разделы и общее.

## Папки

```
web/src/
  app/                    только адреса страниц: page.tsx, layout.tsx, route.ts — тонкие
  modules/                один модуль на раздел сайта
    topics/               темы и стороны позиций
    glossary/             словарь терминов
    videos/               видео как дополнительный материал
    findings/             «Новые находки» и «Не найдено в источниках»
    quiz/                 тесты
    history/              историческая линия
    origins/              истоки и связи с другими учениями
    sira/                 жизнеописание пророка: события, места, люди, даты
    assistant/            ассистент по источникам
    quran/                суры, поиск, карта Корана, нити историй, перевод
    hadith/               сборники хадисов, похожие тексты
    library/              книги по разделам и страницам, тексты других религий
    accounts/             вход, свой пароль, учётные записи
    knowledge/            карта знаний: разделы, темы, термины одним графом
    galaxy/               «Галактика библиотеки»: вся библиотека графом в 2D и 3D
    reports/              «Сообщить об ошибке»: заметка читателя о странице для администратора
    bookmarks/            закладки читателя и «продолжить чтение»
  shared/                 общее для всех разделов; от модулей не зависит
    db.ts                 подключение к базе
    auth/                 сеанс, проверка входа и роли, пароли, предпросмотр черновиков
    addresses/            разбор и запись адресов и ссылок: «2:255», «Бухари 1», «Ибн Хишам 1:235», тексты других религий
    text/                 арабский текст для поиска, условия поиска
    import/               разбор файлов источников (их запускает web/scripts/import-sources.ts)
    forms/                статусы, степени признания, ошибки форм, общий набор форм админки
    ui/                   компоненты shadcn/ui и поля форм
    layout/               каркас страницы, шапка, полоски предпросмотра
    content/              текст со ссылками на адреса, строки стихов, карта региона
    graph/                граф связей на Sigma.js: GraphView, цвета из темы
    i18n/                 сборка надписей и plural()
```

Устройство модуля (на примере «Тем»):

```
modules/topics/
  index.ts                открытый вход: типы, правила, компоненты
  i18n.ts                 надписи модуля (собирает shared/i18n/ru.ts)
  topic.constants.ts      постоянные значения
  topic.types.ts          типы данных
  topic.validation.ts     проверка ввода (+ .test.ts рядом)
  topic.passages.ts       чистые функции предметной логики (+ .test.ts)
  server/
    index.ts              открытый вход сервера: чтение и запись в базе
    topic.queries.ts      чтение
    topic.commands.ts     запись
    topic.actions.ts      действия форм админки ("use server")
    topic.sql.ts          общие куски запросов, только внутри модуля
  components/
    topic-form/           форма, разбитая на карточки
    topic-page/           разделы публичной страницы
```

`app/` по правилам Next.js содержит адреса страниц, поэтому страницы остаются там, но тонкие: проверить адрес и доступ, взять данные из модуля, отрисовать его компонент.

## Правила

1. **Модуль берут только через открытые входы:** `@/modules/<имя>` (типы, правила, компоненты), `@/modules/<имя>/server` (база, только на сервере) и `@/modules/<имя>/i18n` (надписи, для `shared/i18n/ru.ts`). Забраться глубже нельзя — это проверяет линтер (`web/eslint.config.mjs`), сборка с таким импортом не пройдёт.
2. **Общий код (`shared/`) не зависит от модулей** — тоже проверяет линтер. Единственное исключение — `shared/i18n/ru.ts`, который собирает надписи модулей. Модули могут пользоваться друг другом через открытые входы (темы показывают видео, страницы хадисов — тексты библиотеки).
3. **Внутри модуля файлы ссылаются друг на друга относительными путями** (`../topic.types`).
4. **Окончание имени говорит о роли файла:** `.constants.ts`, `.types.ts`, `.validation.ts`, `.queries.ts`, `.commands.ts`, `.actions.ts`, `.sql.ts`, `.test.ts`; чистая логика — по смыслу: `.passages.ts`, `.calendar.ts`, `.periods.ts`, `.map-layout.ts`. Компоненты — по имени того, что рисуют: `topic-form.tsx`, `main-card.tsx`, `positions-section.tsx`.
5. **Серверный код помечен `import "server-only"`.** Работа с базой не может попасть в браузер: сборка остановится.
6. **Ориентир — до 250–300 строк на файл.** Большая форма или страница делится на карточки и разделы.
7. **Надписи раздела — в `i18n.ts` модуля**; `shared/i18n/ru.ts` подставляет их на прежние места (`messages.topics`, `messages.admin.topicForm` и т. д.), поэтому компоненты читают надписи как раньше.
8. **Тесты лежат рядом с проверяемым файлом.** Тесты понимают пути `@/…` так же, как сайт (`web/vitest.config.ts`); защита `server-only` в тестах заменена пустым модулем, чтобы тест мог взять функцию из входа модуля, который заодно открывает серверный код.
9. **Файлы, которые запускает загрузка источников** (`shared/import/*`, `shared/text/arabic.ts`, `shared/text/plain-key.ts`), ссылаются друг на друга относительными путями с `.ts`: их выполняет Node без сборки.

## Графы

`shared/graph/graph-view.tsx` — общий граф на Sigma.js (WebGL). Модуль готовит данные (`GraphData`: узлы с координатами, посчитанными на сервере, и связи) и палитру: тип узла → токен темы (`--primary`, `--graph-1` … `--graph-4` в `globals.css`). Компонент сам загружает sigma только в браузере, приближает кнопками и колёсиком с Ctrl/⌘, подсвечивает узел с соседями, по клику открывает страницу узла или передаёт выбор (`onSelect`). Рядом с графом на странице всегда есть тот же список текстом. Вид 3D есть только у «Галактики библиотеки» (`modules/galaxy`, 3d-force-graph на three.js): раскладка считается в браузере до первого кадра и дальше не меняется, three.js загружается только при выборе 3D. Общие цвета и затухание (`readColors`, `mix`) — в `shared/graph/graph-colors.ts`.

## Как переносилось и как проверять большие перемены

1. Файлы переносились через `git mv`, чтобы сохранилась история.
2. Поведение не менялось. Перед каждой отправкой — сборка, тесты, линтер и сравнение 72 страниц сайта до и после: текст, ссылки, значки, поля форм. Все 72 совпали; отличались только служебные номера действий форм — Next вычисляет их по пути файла.
3. Проверялись формы всех разделов (сохранение с ошибкой), полный цикл в темах и словаре (создание, правка, удаление) и путь учётной записи (завести читателя, первый вход, смена пароля, закрытая админка).
4. Один раздел — один коммит.

## Что ещё можно улучшить

- Карточка «статус и причина изменения» и кнопка «удалить черновик» почти одинаковы в формах тем и словаря — их можно сделать общими в `shared/forms`.
- Проверка «адреса существуют в библиотеке» повторяется в записи тем и словаря — её можно вынести в `shared/addresses`.
- Несколько страниц в `app/` длиннее 150 строк (жизнеописание, поиск по книгам, раздел книги): их разметку можно перенести в компоненты модулей.
