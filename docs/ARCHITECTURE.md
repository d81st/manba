# Архитектура кода сайта

08.11.2026 · Решение автора: модули в духе Angular, по правилам Next.js. Пробный модуль — «Темы» (`web/src/modules/topics`); остальные разделы переносятся по тому же образцу, по одному модулю за шаг.

## Папки

```
web/src/
  app/                      только адреса страниц: page.tsx, layout.tsx, route.ts
  modules/                  один модуль на раздел сайта
    topics/
      index.ts              открытый вход: типы, правила, компоненты
      i18n.ts               надписи модуля (собирает i18n/ru.ts)
      topic.constants.ts    постоянные значения
      topic.types.ts        типы данных
      topic.validation.ts   проверка ввода (+ .test.ts рядом)
      topic.passages.ts     чистые функции предметной логики (+ .test.ts)
      server/
        index.ts            открытый вход сервера: чтение и запись в базе
        topic.queries.ts    чтение
        topic.commands.ts   запись
        topic.actions.ts    действия форм админки ("use server")
        topic.sql.ts        общие куски запросов, только внутри модуля
      components/
        topic-form/         форма, разбитая на карточки
        topic-page/         разделы публичной страницы
  components/               общее для всех: компоненты shadcn (ui/), шапка, списки аятов и хадисов
  lib/                      общее и ещё не перенесённое: база, вход, арабский текст, поиск
  i18n/                     сборка надписей и plural()
```

`app/` по правилам Next.js содержит адреса страниц, поэтому страницы остаются там, но становятся тонкими: проверить адрес и доступ, взять данные из модуля, отрисовать его компонент. Вся логика раздела живёт в модуле.

После переноса всех разделов общее из `components/` и `lib/` переедет в `shared/` (`shared/db`, `shared/auth`, `shared/arabic`, `shared/ui`, `shared/i18n`).

## Правила

1. **Модуль берут только через открытые входы:** `@/modules/<имя>` (типы, правила, компоненты), `@/modules/<имя>/server` (база, только на сервере) и `@/modules/<имя>/i18n` (надписи, для `i18n/ru.ts`). Забраться глубже нельзя — это проверяет линтер (`web/eslint.config.mjs`, правило `no-restricted-imports`), сборка с таким импортом не пройдёт.
2. **Внутри модуля файлы ссылаются друг на друга относительными путями** (`../topic.types`).
3. **Окончание имени говорит о роли файла:** `.constants.ts`, `.types.ts`, `.validation.ts`, `.queries.ts`, `.commands.ts`, `.actions.ts`, `.sql.ts`, `.test.ts`. Компоненты — по имени того, что рисуют: `topic-form.tsx`, `main-card.tsx`, `positions-section.tsx`.
4. **Серверный код помечен `import "server-only"`.** Работа с базой не может попасть в браузер: сборка остановится.
5. **Ориентир — до 250–300 строк на файл.** Большая форма или страница делится на карточки и разделы.
6. **Надписи раздела — в `i18n.ts` модуля**; `i18n/ru.ts` подставляет их на прежние места (`messages.topics`, `messages.admin.topicForm` и т. д.), поэтому компоненты читают надписи как раньше.
7. **Тесты лежат рядом с проверяемым файлом.** Тесты понимают пути `@/…` так же, как сайт (`web/vitest.config.ts`).

## Как переносится раздел

1. Файлы переносятся через `git mv`, чтобы сохранилась история.
2. Поведение не меняется. Перед отправкой — сборка, тесты, линтер и сравнение страниц раздела до и после: текст, ссылки, поля форм. Для пробного модуля 17 страниц совпали полностью; отличаются только служебные номера действий форм — Next вычисляет их по пути файла.
3. Проверяются формы раздела: сохранение с ошибкой, создание, правка, удаление.
4. Один модуль — один коммит.

Порядок переноса: темы (сделано) → словарь → видео → находки → тесты → историческая линия → истоки и связи → жизнеописание → ассистент → Коран → хадисы → библиотека и загрузка источников → учётные записи → общее в `shared/`.
