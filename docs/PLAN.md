# План: энциклопедия ислама по первоисточникам

Черновик плана подготовки · 17.10.2026

> Источник правды до начала разработки — документ «План: энциклопедия учения с дебатами» в Claude. После старта разработки источником правды становится этот файл; новые решения записываются сюда.

## Суть идеи

Большая энциклопедия ислама, построенная только на первоисточниках: что это за религия, откуда её источники, что в ней изначально, что пришло из других религий и как она менялась от пророка до наших дней. Цель: человек сам изучает учение и понимает его по оригинальным текстам, без посредников.

- **Главный продукт** — энциклопедия: библиотека первоисточников с навигацией.
- **Отдельный раздел** — дебаты между участниками. По многим вопросам есть разные взгляды: течения внутри ислама, традиция и исследователи. Читатель выбирает взгляд, который хочет изучить, а позже в дебатах участники спорят, опираясь только на источники.
- **Результат этой работы** — план подготовки (концепция), а не готовое приложение.

## Основные принципы

Первоисточник неприкосновенен: ни участники, ни итоги споров не могут его изменить. Правило действует для опубликованного после запуска; на этапе разработки всё можно свободно менять, а после запуска исправления вносятся с сохранением истории.

**Главный принцип — показать все стороны.** Проект не выбирает сторону. Если по вопросу есть разные мнения — течений внутри ислама, традиции и исследователей, разных учёных, — показываются все, каждое со своими источниками и их уровнем. Читатель сам выбирает, что изучать, и сам делает выводы. При этом у каждого мнения видна степень его признания: принято традицией, принято большинством исследователей или остаётся гипотезой меньшинства.

1. **Только первоисточники.** Вся информация энциклопедии взята из первоисточников, написанных людьми этого учения.
2. **Любое утверждение — со ссылкой.** Аргумент без источника не засчитывается.
3. **Оригинал всегда на виду.** Порядок опоры: сначала первоисточник на языке оригинала, затем утверждённый перевод, если он верен оригиналу, и только после них видео как дополнительный материал.
4. **Решения черновые.** Все пункты плана можно уточнять по ходу работы.

## Фазы продукта

Первая фаза — библиотека, энциклопедия, тесты, ассистент и исторические разделы; дебаты переносятся на вторую фазу.

| Фаза | Что входит | Цель |
| --- | --- | --- |
| 1 | Библиотека первоисточников, энциклопедия с интерактивной подачей, карта Корана, словарь терминов, жизнеописание пророка, священные города, сложные темы, тесты, ассистент по источникам, «Истоки и связи», «Ислам и наука», историческая линия | Полная картина источников и книг, разложенная так, чтобы читателю всё было ясно |
| 2 | Дебаты, модерация, дополнительный слой итогов споров | Живое обсуждение поверх готовой базы знаний |

## Ядро: библиотека первоисточников

Основа проекта — каталог, где у каждого фрагмента текста есть постоянный адрес. На этот адрес ссылаются и энциклопедия, и дебаты.

- **Структура:** источник → книга → глава → фрагмент. Ссылка в споре указывает на адрес фрагмента, а не на текст, вписанный вручную. Так любую цитату можно проверить одним нажатием.
- **Уровни авторитетности:** у каждого источника свой уровень. Уровни ведутся отдельно для суннитского и шиитского канонов; Коран — высший уровень для обоих.
- **Оригинал и переводы:** оригинал хранится как первичный текст. Переводы привязаны к тем же фрагментам, поэтому ссылка на перевод и на оригинал ведёт в одно место.
- **Утверждённый список переводов:** допускаются только заранее проверенные переводы, верные первоисточнику.
- **Библиотечная карточка:** у каждого источника есть нейтральная справка: автор, время, уровень, о чём текст. Без толкований, справку проверяет редактор.

### Дополнительные материалы: видео

Видео — дополнительный материал, а не первоисточник: оно помогает понять текст, но не заменяет его.

- **Где хранится.** Само видео не загружается; в каталоге хранится ссылка на пост, в основном YouTube или Telegram-канал.
- **К чему привязано.** Каждое видео связано с источниками, фрагментами или темами, к которым относится, и видно в панели рядом с ними.
- **Отдельная пометка.** Видео помечается как дополнительный материал, чтобы его не путали с первоисточником. Аргументы в тестах и дебатах строятся только на первоисточниках.
- **Проверка ссылок.** Посты могут удалять, поэтому система периодически проверяет, работает ли ссылка, и помечает недоступные.
- **Позже:** комментарии к видео и другим материалам.

Решено: на первой фазе видео добавляет и проверяет один администратор-модератор.

### Коран: общий источник и варианты чтения

Коран — источник высшего уровня и для суннитов, и для шиитов: обе традиции пользуются одним и тем же текстом. При этом у него есть несколько признанных вариантов чтения (кираатов), и их нужно учесть в устройстве библиотеки.

- **Что такое кираат.** Традиция признаёт несколько канонических чтецов, у каждого — передатчики (ривайят). Самые распространённые сегодня — Хафс от Асима (большая часть мира) и Варш от Нафи (в основном Северная и Западная Африка); есть и другие, например Калун.
- **В чём различия.** Основной письменный остов текста общий; различия касаются огласовок, произношения, иногда отдельных букв и слов.
- **Как хранить.** Аят — один фрагмент с одним адресом, а у него несколько версий текста по ривайятам. По умолчанию показывается Хафс, переключатель открывает другие чтения с подсветкой различий.
- **Обе стороны.** Традиция объясняет варианты тем, что все они ниспосланы; исследователи изучают историю текста по древним рукописям. Показываются оба взгляда с источниками.
- **Аналог для изучения:** проект Corpus Coranicum, который собирает рукописи и варианты чтения.

### Переводы и толкования Корана

Кроме вариантов чтения, у Корана много разных переводов, и они сильно отличаются подходом. Часть переводчиков опирается на хадисы и толкования и вносит пояснения прямо в текст перевода.

| Вид | Что это | Пример | Как хранить |
| --- | --- | --- | --- |
| Буквальный (академический) перевод | Передаёт текст максимально близко к оригиналу, без пояснений | Перевод Крачковского | Версия-перевод аята |
| Смысловой перевод | Передаёт смысл; пояснения из толкований и хадисов вставлены в текст | Перевод Эльмира Кулиева | Версия-перевод аята; вставки переводчика размечены отдельно |
| Толкование (тафсир) | Отдельное произведение-комментарий к аятам, со ссылками на хадисы и других учёных | Тафсир Ибн Касира (написан на арабском; существуют его переводы) | Самостоятельное произведение со своим уровнем, связанное с аятами связью «толкование» |

- **Вставки переводчика видны.** Пояснения в скобках выделяются иначе, чем сам перевод, чтобы читатель видел, что есть в оригинале, а что добавил переводчик.
- **На чём основан перевод.** В карточке перевода: переводчик, год, язык, вид перевода и на какие толкования и хадисы он опирается. Если источники вставок известны, они даются ссылками на фрагменты.
- **Сравнение переводов.** Несколько переводов одного аята рядом под оригиналом.
- **Отзывы о переводах.** Если перевод критикуют, это показывается с источниками, как и любое другое мнение.

### Черновик нашей схемы

- **Произведение.** Постоянный короткий идентификатор (например, `quran`, `bukhari`), названия на нескольких языках, категория, канон (общий, суннитский, шиитский, внешний), уровень авторитетности.
- **Схема произведения.** Уровни с названиями и типом номера: для Корана сура → аят; для сборника хадисов книга → глава → хадис.
- **Адрес.** Читаемый («Коран 2:255») и машинный (`quran.2.255`); диапазоны (`quran.2.255-257`).
- **Альтернативная нумерация.** Таблица соответствий для разных изданий, например разных нумераций хадисов, чтобы найти фрагмент по любому номеру.
- **Версия.** Произведение + язык + название версии + тип (оригинал, кираат, перевод) + переводчик + источник + лицензия + статус сверки + признак главной версии.
- **Тафсир** — отдельное произведение, связанное с аятами связью «толкование», а не версия Корана.
- **Текст.** Хранится по паре «адрес + версия» в двух видах: с разметкой (включая вставки переводчика) и очищенный для поиска.
- **Связь.** Адрес ↔ адрес + тип + основание + степень уверенности + кто добавил.

## Энциклопедия и навигация

Главный вход — по источникам, а темы и вопросы служат указателями на те же фрагменты.

| Вход | Как выглядит | Роль |
| --- | --- | --- |
| По источникам | Список источников по уровням, самые авторитетные сверху; внутри книга → глава → фрагмент | Главный |
| По темам | Тема (например, ключевые понятия) и подборка фрагментов из разных источников | Указатель |
| По вопросам | «Что учение говорит о X?» и ответ из цитат | Указатель |

Темы и вопросы не содержат собственного текста, только ссылки на фрагменты. Поэтому правило неизменности ядра соблюдается автоматически.

### Подача: по кирпичикам и интерактивно

Каждая наглядная часть строится из данных каталога, а не рисуется вручную, поэтому она всегда точна и меняется вместе с каталогом.

- **Карта книги.** Интерактивное дерево: книга → главы → фрагменты; можно раскрывать уровень за уровнем.
- **Лента времени.** Когда был написан каждый источник, в каком порядке и кем.
- **Граф связей.** Как источники и фрагменты ссылаются друг на друга, включая связи с текстами других религий.
- **Карточки и словарь.** Библиотечная карточка источника и определения терминов по нажатию.
- **Путь читателя.** Рекомендуемый порядок изучения от базовых источников к сложным и отметки прочитанного.

## Карта Корана

Отдельный раздел «Изучение Корана»: при открытии видна карта всего Корана, где каждая сура — блок, а внутри него клетки-аяты. Карта показывает, как устроен текст, какие места повторяются и какие связаны с другими религиями.

**Устройство карты**

- **Сетка сур.** 114 блоков в порядке мусхафа; размер блока зависит от числа аятов, внутри — клетки аятов.
- **Уровни приближения.** Весь Коран → джуз (одна из 30 традиционных частей для чтения) → сура → аят.
- **Переход к тексту.** Нажатие на аят открывает его в библиотеке с оригиналом, переводами, кираатами, толкованиями и видео.

**Слои (переключаются как линзы)**

| Слой | Что подсвечивает |
| --- | --- |
| Связи с другими религиями | Аяты с параллелями, цвет по религии, насыщенность по числу связей. Например, история Юсуфа (сура 12) и книга Бытия, рассказ о спящих в пещере (сура 18) и христианская легенда о семи спящих отроках |
| Повторы | Истории и формулы, которые встречаются в нескольких местах: например, рассказ о Мусе в разных сурах или рефрен суры «Милостивый», повторённый 31 раз |
| Темы | Пророки и истории, законы, вероучение, описания будущей жизни и другие темы энциклопедии |
| Место откровения | Мекканские и мединские суры по традиции; рядом — хронология исследователей, обе с источниками |
| Кирааты | Аяты, где варианты чтения расходятся |
| Толкования и хадисы | Сколько тафсиров и хадисов связано с аятом |
| Путь читателя | Что уже прочитано |

**Карточка при наведении**

- **Аят:** адрес (сура:аят), начало текста в оригинале и одном переводе, место откровения, темы, связи по религиям с короткими подписями, где ещё повторяется эта история, есть ли расхождения в чтениях, сколько толкований, хадисов и видео.
- **Сура:** название на арабском и его перевод, число аятов, порядок в мусхафе и в хронологиях, мекканская или мединская, главные темы, сколько связей с другими религиями.
- **На телефоне** наведения нет, поэтому карточка открывается касанием.

**Нити историй**

Можно выбрать историю, например о Мусе, Ибрахиме, Нухе или Марьям: на карте подсвечиваются все аяты, где она рассказана, и соединяются линией в порядке текста. Рядом показываются параллельные места из Библии и других текстов с переходом к сравнению фрагментов.

**Правила**

- Всё на карте строится из данных каталога: связи с основанием, темы и повторы — только проверенные.
- У связей пометка «параллель» или «заимствование» и обе трактовки, как в разделе «Истоки и связи».
- Для 6236 клеток лучше рисовать на canvas, а не в SVG, чтобы карта работала быстро и на телефоне.

## Словарь терминов

Новички спотыкаются о базовые термины: одно слово обозначает целое понятие, как термины в программировании или электронике. Словарь — отдельный большой раздел, и он же служит основой ассистента.

**Карточка термина**

- **Название:** на арабском, в транслитерации и в переводе.
- **Коротко:** определение в одно-два предложения для новичка.
- **Подробно:** развёрнутое объяснение с примерами — ссылками на конкретные аяты и хадисы.
- **Связанные термины:** граф понятий, например насих → мансух → насх.
- **Разные определения:** если школы или учёные понимают термин по-разному, показываются все варианты с источниками.

**Как встречается на сайте**

- Термины в любом тексте подсвечиваются; нажатие показывает короткое определение.
- Есть «первые 50 терминов» — минимальный набор для новичка.
- Вопросы по терминам входят в тесты.

**Пример различия понятий.** Мекканские и мединские аяты — деление по месту и времени откровения. Насх — отмена одного предписания другим: насих — отменяющий аят, мансух — отменённый. Понятия связаны, потому что отменяющий аят обычно более поздний, но это разные термины. При этом сколько аятов действительно отменено, учёные спорят, и это тоже показывается.

## Жизнеописание пророка (сира)

Большой самостоятельный раздел о жизни пророка: от рождения до смерти, со всеми людьми и событиями вокруг него.

**Что охватывает**

- **Происхождение и детство:** когда и где родился, родители, род и племя, родственники, кормилица, окружение, в котором вырос.
- **Мекканский период:** первое откровение, кто первым поддержал, кто помогал и кто противостоял.
- **Переселение в Медину** и мединский период: община, договоры, сражения.
- **Объединение Аравии:** походы, взятие Мекки, последние годы.

**Интерактивная подача**

- **Лента жизни** — те же события на общей исторической линии.
- **Карта Аравии** с местами событий и маршрутами переселения и походов.
- **Граф людей:** родственники, сподвижники, противники; у каждого своя карточка.
- **Карточки событий и сражений:** дата, участники, итог, связанные аяты и хадисы.

**Источники и обе стороны**

- Традиционные источники: Коран, хадисы и классические жизнеописания, например сира Ибн Исхака в передаче Ибн Хишама, сочинения аль-Вакиди и Ибн Сада.
- Исследователи обращают внимание, что жизнеописания записаны спустя век и больше после событий, и оценивают их достоверность по-своему. Показываются обе позиции.

## Священные города

Отдельный раздел о городах, священных в исламе, и их истории.

- **Мекка** — главный священный город, место Каабы.
- **Медина** — город пророка, второй по значению.
- **Иерусалим** — третий священный город, первое направление молитвы; мечеть аль-Акса.
- **Святыни шиитской традиции** — например Неджеф, Кербела, Мешхед, Кум.

У каждого города: история до и после ислама, роль в учении, события сиры и исторической линии, связанные аяты и хадисы, место на карте.

**Гипотезы о происхождении городов.** Есть спорные версии, например о том, что упомянутая в Коране Бекка — не Мекка или что ранним центром была Петра. Они показываются, но с честной пометкой степени признания: что принято традицией, что принято большинством исследователей, а что остаётся гипотезой меньшинства.

## Сложные темы

В исламских текстах есть места о войне, джихаде и отношении к иноверцам, которые сегодня вызывают тревогу и споры. Проект их не скрывает: умалчивание нарушило бы главный принцип и подорвало бы доверие к остальному. Но показывать их нужно особенно аккуратно — с текстом, контекстом и всем спектром толкований.

**Как подаётся каждое такое место**

1. **Сам текст полностью** — в оригинале и утверждённых переводах, без вырывания из контекста.
2. **Окружающие аяты** — что сказано до и после.
3. **Обстоятельства** — повод ниспослания по традиционным источникам и исторический фон: войны и договоры того времени.
4. **Спектр толкований** с источниками и степенью признания: классические правоведы, современные богословы основных течений, сторонники историко-контекстного прочтения, критики ислама.
5. **Связанные места** — например, аяты, которые часто приводят вместе: о мече и о джизье (9:5, 9:29), о сражении только с теми, кто нападает (2:190), об отсутствии принуждения в религии (2:256), о добром отношении к тем, кто не воюет (60:8).
6. **Связь с насхом** — одни учёные считают, что поздние аяты о войне отменили ранние мирные, другие это отвергают; показываются обе позиции.

**Термины.** У слова «джихад» несколько значений — от личного усилия до вооружённой борьбы. Словарь показывает все значения и кто как их понимает.

**Вопрос реформы.** Должно ли толкование меняться со временем — сам по себе спорный вопрос внутри ислама: одни учёные выступают за переосмысление, другие за сохранение классического понимания. Проект показывает этот спор, а не отвечает на него.

**Защита от злоупотреблений**

- Тексты подаются как предмет изучения, а не как призыв; контекст и толкования всегда рядом с текстом, без отдельной подачи «голых» цитат.
- Можно показать, как такие места используют экстремисты и как им возражают богословы, но без размещения самих экстремистских материалов: их распространение запрещено и в Узбекистане, и во многих других странах.
- Подбор толкований по этим темам обязательно проверяет специалист.

**Доступ к сайту**

Материалы не делятся на уровни доступа, чтобы ничего не мешало изучению: весь сайт целиком открывается после входа по логину и паролю. Это не зависит от стека.

- **Весь сайт — после входа.** Всё содержимое, включая «Сложные темы», доступно любому вошедшему пользователю одинаково.
- **Закрытый режим на время разработки.** Регистрация только по приглашению и запрет индексации поисковиками. Доступ «только по ссылке» защитой не считается.
- **Ограничения по странам** при необходимости настраиваются позже на уровне CDN, например Cloudflare.

## Истоки и связи с другими учениями

Учение сложилось не с нуля: часть его взята из других религий и переосмыслена. Этот раздел показывает, что и откуда пришло, и входит в базу первой фазы.

**Как устроена связь**

Каждая связь — пара фрагментов: фрагмент ислама и фрагмент текста другой религии. У связи есть:

- **Тип:** прямая цитата, пересказ, общий сюжет или мотив, общее понятие.
- **Основание:** на чём держится утверждение о связи, например исследование или указание в самих текстах. Связь без основания не публикуется.
- **Степень уверенности.** Если доказано, что текст заимствован, связь помечается как «заимствование»; если тексты просто похожи — как «параллель».

Тексты других религий хранятся в библиотеке отдельной категорией «внешние источники». Они не считаются первоисточниками ислама.

**Две трактовки сходства.** Сходство с текстами других религий объясняется по-разному: исследователи часто видят заимствование, а исламская традиция — общий божественный источник и предшествующие откровения. Чтобы раздел оставался нейтральным, у каждой связи показываются обе трактовки с их источниками, а вывод делает читатель.

**Интерактивная подача**

- **Карта учений.** Граф, где учения — группы узлов, а линии — связи между фрагментами; карту можно листать, приближать и фильтровать по учению, типу связи и теме.
- **Хронология.** Лента времени показывает, какой текст появился раньше, то есть в каком направлении шло заимствование.
- **Сравнение рядом.** Два фрагмента в двух колонках, совпадающие места подсвечены, у каждого оригинал и перевод.
- **Переход в библиотеку.** Любой узел открывает фрагмент с его панелью.

## Историческая линия

Интерактивная лента времени от пророка до наших дней: когда что появилось в исламе и кто за этим стоял. Каждое событие опирается на источники.

**Слои ленты**

- **Правители:** пророк, праведные халифы, затем династии — Омейяды, Аббасиды, Османы и другие — до наших дней.
- **Тексты:** когда записывались и собирались тексты — сведение Корана в единый свод, составление сборников хадисов, толкований, жизнеописаний пророка.
- **Учение и практика:** когда формировались правовые школы, течения, обряды и понятия, и что из этого существовало до ислама.
- **Связи:** события из раздела «Истоки и связи» на той же шкале, чтобы видеть, что было до ислама и что после.

**Правила**

- **Каждое событие — с источником.** Дата, участники и суть подкреплены ссылками на фрагменты.
- **Спорные даты и версии.** Если источники расходятся, показываются все версии с их основаниями, а не одна.
- **Масштаб.** Ленту можно приближать от столетий до отдельных лет и фильтровать по слоям.

- [x] Чей канон источников берётся за основу уровней? Решено: оба, суннитский и шиитский, каждый со своими сборниками и оценками. Коран — общий источник высшего уровня для обоих.
- [x] Что означают противоположные позиции? Решено: не только две и не только внутри ислама. Читатель сам выбирает взгляд: течения внутри ислама, взгляд традиции, взгляд исследователей.

## Тесты

Тесты проверяют понимание и сразу показывают, откуда берётся правильный ответ.

- **Вопрос построен из фрагментов.** У каждого вопроса есть набор фрагментов первоисточников, на которых он основан.
- **После ответа — источники.** При любом ответе, правильном или неправильном, показывается фрагмент и список всех источников, подтверждающих правильный ответ, со ссылками на них.
- **Уровни.** Уровень вопроса равен уровню авторитетности источников, на которых он построен: вопросы по самым авторитетным источникам стоят на верхнем уровне.
- **Связь с энциклопедией.** Из любого источника в результатах можно перейти к фрагменту в библиотеке.

- [x] Что означают уровни тестов? Решено: уровень авторитетности источников, на которых построен вопрос.
- [x] Показывать источники при неправильном ответе? Решено: да, чтобы человек учился на ошибке.
- [x] Кто составляет и проверяет вопросы? Решено: пока модератор.

## Ассистент по источникам

Собственный помощник: пользователь задаёт вопрос обычными словами и получает только те источники и материалы, которые относятся к этому вопросу. Сначала он работает внутри проекта, позже его можно выделить в отдельный модуль для других приложений.

**Как работает**

1. **Разбор вопроса.** Вопрос раскладывается на кирпичики: подвопросы и ключевые понятия учения.
2. **Поиск по каждому кирпичику.** Для каждого подвопроса ищутся фрагменты в оригиналах и утверждённых переводах: по словам и по смыслу.
3. **Ранжирование.** Найденные фрагменты упорядочиваются по уровню авторитетности источника и близости к контексту вопроса, по тем же правилам, что и во всём проекте.
4. **Ответ.** Результат показывается списком и графом: подвопросы и фрагменты — узлы, линии — какой фрагмент отвечает на какой подвопрос и как фрагменты связаны между собой. Цвет узла показывает уровень источника.
5. **Переход в библиотеку.** Любой узел открывает фрагмент в библиотеке с его панелью, переводами и видео.

**Версии ассистента**

Базовая версия пишется обычным кодом, без языковой модели; модель добавляется в следующих фазах.

| Версия | Как понимает вопрос | Что показывает |
| --- | --- | --- |
| Базовая (фаза 1) | Обычный код: слова вопроса приводятся к начальной форме и сопоставляются со словарём терминов, синонимами и темами; дальше полнотекстовый поиск по фрагментам | Список и граф фрагментов, без собственного текста |
| Улучшенная | Добавляется поиск по смыслу (векторы фрагментов) | То же, но находит и перефразированные вопросы |
| С моделью | Языковая модель раскладывает вопрос на подвопросы | Позже — связующий текст со ссылками |

В базовой версии качество ответов зависит от словаря терминов и синонимов на всех языках. Поэтому словарь — ключевая часть базы, его ведёт администратор-модератор.

**Правила**

- **Только из источников.** На первом запуске ассистент не пишет собственный текст: он только подбирает и раскладывает фрагменты, а выводы пользователь делает сам. Языковая модель нужна лишь для разбора вопроса и поиска. Если подходящих фрагментов нет, ассистент прямо сообщает об этом.
- **Помощь с сайтом.** Ассистент также объясняет, как пользоваться сайтом и где что искать.
- **Отдельный модуль.** Ассистент — отдельный сервис со своим API, поэтому его можно подключать к другим приложениям.

- [x] Пишет ли ассистент свой связующий текст? Решено: на первом запуске нет, только подбор и раскладка фрагментов. Позже можно сделать его гибче и добавить связующий текст.
- [x] В какой фазе он появляется? Решено: базовая версия в первой фазе, с самого начала разработки.
- [x] Модель на своём сервере или через внешний API? Решено: в первой фазе модели нет, ассистент пишется обычным кодом; связка с моделью — в следующих фазах.

**Рекомендация по модели.** Для следующих фаз, когда к ассистенту подключится модель, подойдёт смешанный вариант:

- **Векторы фрагментов — локально.** Многоязычная модель векторов (например, bge-m3) работает на обычном сервере без видеокарты. Тексты источников никуда не отправляются.
- **Разбор вопроса — через внешний API.** Это быстрый старт без дорогих серверов с видеокартами; при небольшом числе пользователей обходится дёшево. Наружу уходит только сам вопрос, а не тексты источников, потому что ассистент ничего не пишет.
- **Замена без переделки.** Модель подключается через отдельный слой в сервисе ассистента, поэтому позже её можно заменить на локальную (Ollama или vLLM), когда вырастет нагрузка или понадобится полная приватность вопросов.

## Дебаты (фаза 2)

Спор выигрывает аргумент с источником большего веса. Голосование ничего не решает и нужно только для сбора данных.

**Ход спора**

1. Участники заранее выбирают тему. Сменить её можно только по согласию обеих сторон.
2. Один задаёт вопрос, другой отвечает со ссылкой на фрагмент первоисточника или утверждённого перевода.
3. В любой момент можно задать встречный вопрос.
4. Язык спора выбирают участники. По умолчанию это язык, понятный обоим. Цитаты всегда в оригинале, перевод рядом.

**Как оценивается аргумент**

- **Вес источника** — главный фактор доверия.
- **Один уровень, разные ответы** — выше тот источник, который ближе к контексту вопроса (правило ещё уточняется).
- **Неверная цитата** — если источник вырван из контекста или не подтверждает сказанное, его вес не помогает; это проверяет модератор.
- **Голосование** — вторично: мониторинг и накопление данных о том, как люди рассуждают.

## Роли

Ключевые роли — модератор и редактор: у них разные задачи, но это может быть один человек.

| Роль | Когда работает | Что делает |
| --- | --- | --- |
| Модератор | Во время спора | Следит за правилами; проверяет, что цитата действительно подтверждает утверждение |
| Редактор | После спора | Проверяет итог спора перед публикацией; проверяет библиотечные карточки источников |
| Участник | В споре | Задаёт вопросы и отвечает только со ссылками на первоисточники |
| Читатель | Всегда | Изучает энциклопедию и итоги споров |

**На первой фазе** все роли проверки совмещает один человек — администратор-модератор. Он добавляет и проверяет источники, переводы, видеоматериалы, вопросы тестов и словарь терминов.

```
   │ привязан к фрагментам
   ▼
Ядро: первоисточники и утверждённые переводы — неизменно
(дебаты цитируют фрагменты ядра, но не меняют его)
```

Читатель открывает фрагмент и видит, в каких спорах он обсуждался, со ссылками на итоги. Сам текст первоисточника при этом не меняется.

## Аналоги

Единой платформы со всеми частями не найдено. Новизна проекта — в сочетании проверенных подходов с обязательной ссылкой на фрагмент первоисточника.

| Платформа | Что делает | Что взять | Чего не хватает |
| --- | --- | --- | --- |
| [Sefaria](https://designing-knowledge.siggraph.org/wp/?p=126) | Библиотека еврейских текстов: версии и переводы, выровненные по фрагментам, связи между текстами, пользовательские подборки | Структуру фрагментов, выравнивание оригинала и перевода, слой пользовательских материалов рядом с ядром; открытые данные и API | Дебатов и уровней достоверности |
| [Sunnah.com](https://beta.sunnah.com/about) | Сборники хадисов со степенью достоверности и учёным, который её дал | Уровни источников, единую нумерацию фрагментов | Дебатов |
| [Kialo](https://en.wikipedia.org/wiki/Kialo) | Дебаты деревом: тезис, аргументы «за» и «против», оценка голосованием | Структуру спора и встречных аргументов | Обязательных источников: по [критике](https://www.lesswrong.com/posts/g3odvaj8opqCF9egv/kialo-an-online-discussion-platform-that-attempts-to-support), побеждают популярные аргументы, а не подкреплённые |

На этапе исследования изучить эти платформы, начиная с Sefaria и Corpus Coranicum.

### Что берём у Sefaria — для библиотеки

- **Панель рядом с фрагментом.** При нажатии на фрагмент сбоку открываются его переводы, связанные фрагменты и итоги споров, где он обсуждался.
- **Связи между фрагментами.** Перекрёстные ссылки между источниками, в том числе на параллельные места в текстах других религий.
- **Несколько переводов на выбор.** Все утверждённые переводы выровнены по фрагментам; читатель переключает их, оригинал остаётся на месте.
- **Словарь терминов.** Нажатие на термин показывает его краткое нейтральное определение.
- **Сканы рукописей и изданий.** Скан страницы привязан к фрагменту, и любой может сверить цифровой текст с оригиналом.
- **Офлайн-режим.** Мобильное приложение может скачать всю библиотеку.
- **Позже:** открытые данные и API, автоматические ссылки на наши фрагменты с внешних сайтов.
- **Не берём:** переводы, которые правят пользователи. У нас только утверждённый список.

### Что берём у Sunnah.com — для уровней источников

- **Уровень виден на каждом фрагменте** вместе с тем, кто его присвоил.
- **Разные оценки рядом.** Если специалисты оценивают источник по-разному, показываем все оценки, как в [сравнении оценок хадисов](https://parallelquran.com/grading-lens/).
- **Двойная нумерация.** Номер по оригинальному изданию и номер по переводу, чтобы человек с печатной книгой нашёл нужный фрагмент.
- **Отметка «текст проверен».** Пока источники оцифровываются, у каждого фрагмента виден статус сверки с оригиналом.
- **Карточки авторов.** Расширение библиотечной карточки: кто автор или передатчик текста и когда жил.

### Что берём у Kialo — для дебатов

- **Спор в виде дерева.** Вопрос → ответы → встречные вопросы как ветки.
- **Карта спора.** Наглядная схема всего дерева для читателей итогов.
- **Короткие аргументы.** Ограничение длины одного аргумента держит спор сфокусированным.
- **Источник обязателен на уровне формы.** Ответ нельзя отправить без ссылки на фрагмент.
- **Теги споров** связывают итоги с темами энциклопедии.
- **Выгрузка данных** для анализа рассуждений.
- **Позже:** учебный режим для групп, как Kialo Edu.
- **Урок:** сортировка по голосам продвигает популярное, а не подкреплённое. Это подтверждает решение, что решает вес источника.

### Что берём у Corpus Coranicum — для Корана и связей

Академический проект Берлин-Бранденбургской академии наук: документация текста Корана, база параллельных текстов других традиций и комментарий.

- **Две линии передачи текста с равным весом.** Письменная (рукописи) и устная (варианты чтения). У нас: сканы рукописей и кирааты у каждого аята.
- **Каталог рукописей.** Manuscripta Coranica содержит больше 50 000 снимков ранних рукописей из более чем 95 собраний. У нас: привязка снимков рукописей к аятам и их датировки как данные для исторической линии.
- **Варианты чтения пословно.** У нас: подсветка различий кираатов по словам.
- **Тексты окружения Корана.** База еврейских, христианских, староарабских и других текстов, связанных с конкретными местами Корана. Прямой образец для «Истоков и связей».
- **Словарь и библиография.** У нас: словарь терминов и список исследований как оснований для связей.
- **Свой шрифт.** Обычные арабские шрифты показывают не все нужные знаки. У нас: проверить шрифты для арабского текста заранее.
- **Хронология сур.** У нас: слой на исторической линии с исследовательской хронологией рядом с традиционной.
- **Права на изображения.** Часть снимков недоступна из-за отсутствия прав. У нас: заранее выяснить лицензии; проект как исследовательский завершился в 2024 году, его базы продолжает общество Corpus Coranicum e.V.

## Что заложить с самого начала

Моменты, которые дорого добавлять задним числом.

**Данные и тексты**

- **Права и лицензии.** У каждого текста, перевода и скана должна быть лицензия. Например, Sunnah.com запрещает выгрузку своих данных. Нужны разрешения или открытые корпуса. Арабские оригиналы классических текстов, как правило, общественное достояние; ограничения обычно касаются современных переводов, оценок и составленных баз данных. Копия с другого сайта или скриншот прав не дают.
- **Готовые цифровые корпуса вместо OCR.** Распознавать арабский текст со сканов трудно и дорого; где возможно, брать уже оцифрованные открытые тексты.
- **Единая схема адресов.** Сура:аят для Корана, нумерация хадисов по конкретным изданиям — утвердить до первой строки кода.
- **Арабский текст.** Нормализация Unicode, поиск с огласовками и без, письмо справа налево, подходящие шрифты.
- **Журнал изменений.** Ядро неизменно, но ошибки оцифровки исправляются; каждое исправление записывается: кто, когда и почему.

**Люди и правила**

- **Консультанты.** Есть знакомый специалист, к которому можно обращаться по источникам, их загрузке и использованию. Для проверки уровней и связей полезен также взгляд специалистов обеих традиций и академических исследователей.
- **Редакционная политика.** Письменные правила нейтральности, порядок исправлений и жалоб читателей.
- **Узкое место.** Один администратор-модератор — заранее продумать, как подключать помощников.

**Право и безопасность**

- **Законодательство.** В Узбекистане изготовление, ввоз и распространение материалов религиозного содержания, включая размещённые в интернете, допускаются только после государственной религиоведческой экспертизы Комитета по делам религий. До запуска проверить требования с юристом, а также законы стран, где будут читатели. Сервер планируется за рубежом, но законы обычно применяются к тому, кто размещает материалы, а не только к месту сервера, поэтому проверка всё равно нужна.
- **Приватность.** Интерес к религии — чувствительные данные: при регистрации собирать минимум данных, статистику хранить обезличенно.
- **Защита.** Тема может привлекать атаки и злоупотребления: CDN с защитой от DDoS, модерация, ограничения на действия.

**Продукт**

- **Языки интерфейса** (например, русский, узбекский, английский) — отдельно от языков источников.
- **Мобильная версия и доступность** с первого дня.
- **Резервные копии и экспорт данных.**
- **Название, домен, бюджет** на хостинг и лицензии.

**Пополнение базы без поломок**

Новые знания будут появляться всё время, поэтому база с самого начала строится так, чтобы её можно было пополнять, не ломая работающий сайт.

- **Только добавление.** Новые источники, переводы, кирааты, связи, темы, видео и вопросы тестов добавляются рядом с существующими и ничего не меняют. Неизменность ядра означает, что не меняется уже опубликованный текст, а не что нельзя добавлять новое.
- **Постоянные адреса.** Идентификаторы и адреса никогда не переименовываются и не используются повторно. Если источник нужно убрать, он помечается как снятый, а старый адрес ведёт на пояснение.
- **Статусы: черновик → на проверке → опубликовано.** Новое сначала видно только администратору-модератору, затем проверяется и только потом появляется на сайте.
- **Предпросмотр.** Отдельная тестовая копия сайта, где новое можно посмотреть до публикации.
- **Проверки при загрузке.** Перед сохранением система проверяет, что адрес существует, лицензия указана, дубликатов нет, связь имеет основание.
- **Исправления с историей.** Ошибка оцифровки исправляется новой версией текста; старая сохраняется в журнале, адрес не меняется.
- **Обновление страниц без остановки.** После публикации пересобираются только затронутые страницы; сайт продолжает работать.
- **Резервная копия перед массовой загрузкой** и возможность откатить загрузку целиком.
- **Панель администратора.** Добавлять материалы можно без программирования.

Трудно поменять задним числом только саму схему адресов, поэтому её утверждают до начала кода.

**Новые находки извне**

Пример: в Instagram или YouTube попалось видео с хадисом — текст, перевод, сборник и номер, — а в нашей базе его нет. Пост в соцсети — не источник, а наводка, которую нужно проверить по первоисточнику.

1. **Записать наводку.** В панели администратора есть очередь «Новые находки»: ссылка на пост, какой сборник и номер указаны, дата.
2. **Поискать у себя.** Есть ли этот сборник в библиотеке, и нет ли хадиса под другим номером — разные издания нумеруют по-разному, здесь помогает таблица альтернативных нумераций.
3. **Сверить с оригиналом.** Найти сборник в признанном издании, проверить номер, арабский текст и оценку достоверности; при сомнениях спросить специалиста.
4. **Если подтвердилось** — добавить фрагмент или весь сборник обычным путём (черновик → проверка → публикация) с лицензией. Само видео можно привязать к фрагменту как дополнительный материал. Перевод из видео не используется: показываются оригинал и утверждённый перевод.
5. **Если не подтвердилось** — в ядро не добавлять. Находка остаётся в очереди со статусом «не найдено в указанном источнике» и пояснением, что именно не совпало.

Статусы находки: новая → проверяется → подтверждена или не подтверждена.

- [ ] Нужен ли на сайте раздел «Не найдено в источниках»: тексты, которые приписывают сборнику, но которых там нет, с указанием, где искали?

## Этапы подготовки

Сначала содержание и правила, затем технические решения; стек выбирается одним из последних шагов.

1. **Изучение учения.** Собрать первоисточники, понять их структуру и в чём расходятся взгляды.
2. **Каталог источников.** Перечень источников, их уровни, библиотечные карточки, список утверждённых переводов.
3. **Модель данных.** Как адресуется каждый фрагмент, как к нему привязаны переводы, кирааты, видео, связи и итоги споров.
4. **Регламент дебатов.** Правила спора, критерии проверки цитат для модератора, порядок проверки итогов редактором.
5. **Изучение аналогов.** Разобрать Sefaria (данные и API), Sunnah.com, Kialo и Corpus Coranicum.
6. **Сценарии и функции.** Что делают читатель, участник, модератор и редактор; состав первой версии.
7. **Выбор стека.** По объёму материалов, языкам и функциям из шагов 1–6.
8. **Итоговая концепция.** Сведение всех решений в окончательный план.

## Предварительный стек

Предварительный выбор: Next.js + NestJS + PostgreSQL + поисковый движок + Redis. Окончательно утверждается на шаге 7.

**Нагрузка.** Ядро неизменно, поэтому страницы источников можно собрать заранее и раздавать через CDN: даже очень много прочтений почти не нагружают сервер. Реальная динамическая нагрузка — только дебаты.

| Часть | Технология | Зачем |
| --- | --- | --- |
| Фронтенд | Next.js | Страницы источников генерируются заранее (SSG/ISR), их хорошо индексируют поисковики; поддержка письма справа налево |
| Бэкенд | NestJS (TypeScript) | Модульная структура: источники, дебаты, модерация, пользователи |
| База данных | PostgreSQL | Источники, фрагменты с постоянными адресами, переводы, уровни, споры; иерархия «книга → глава → фрагмент» через `ltree` |
| Поиск | OpenSearch или Meilisearch | Полнотекстовый поиск на многих языках: OpenSearch сильнее в морфологии сложных языков, Meilisearch проще в запуске |
| Дебаты в реальном времени | WebSocket + Redis | Redis пересылает сообщения между серверами, поэтому споры масштабируются горизонтально; он же служит кэшем |
| Файлы | S3-совместимое хранилище | PDF и сканы источников |
| Обработка источников | Python (PyMuPDF, OCR Tesseract) | Отдельный конвейер: PDF превращается во фрагменты; разовая работа, сайт не нагружает |
| Инфраструктура | Docker, CDN (например, Cloudflare) | Docker с начала; Kubernetes — только при реально большой нагрузке |

**Для ассистента добавляется (в следующих фазах):**

- **Сервис ассистента** — Python (FastAPI) как отдельный модуль со своим API.
- **Поиск по смыслу** — векторы фрагментов в PostgreSQL через `pgvector`, вместе с полнотекстовым поиском.
- **Языковая модель** — локальная (например, через Ollama или vLLM) или внешний API.
- **Граф ответов** — библиотека для 2D-графов в браузере, например Cytoscape.js или React Flow.

**Первая версия проще:** Next.js + Supabase. Supabase даёт PostgreSQL, авторизацию и realtime. Позже бэкенд можно вынести в NestJS, не меняя базу.
