# Резервные копии

Решение автора 31.10.2026: бесплатно, без нагрузки на сайт, раз в неделю.

**Что копируется.** Только то, что сделано руками: темы, позиции, термины, стороны, отметки о похожих хадисах, места и всё жизнеописание пророка, связи «Истоков», журнал изменений (`change_log`). Тексты источников (Коран, хадисы, книги, внешние тексты) не копируются: они лежат в `data/sources/` и загружаются заново при запуске на пустой базе (`web/scripts/import-sources.ts`).

**Два уровня.**

1. **Снимки внутри базы** (миграция 019). Функция `take_editorial_snapshot(причина)` сохраняет все эти таблицы одной строкой JSON в `editorial_snapshots`; хранятся последние 8 снимков (около 0,1 МБ каждый). На Supabase её раз в неделю вызывает планировщик `pg_cron` (задание `manba-editorial-snapshot`, воскресенье 03:17 UTC). Защищает от ошибочной правки или удаления.
2. **Копия вне базы** — закрытый репозиторий `d81st/manba-materials`, папка `backups/`: GitHub Actions каждое воскресенье в 03:47 UTC делает `pg_dump` этих таблиц и снимков и сохраняет коммитом (история версий — в git). Защищает от потери самой базы. Нужен секрет `DATABASE_URL` в настройках репозитория (Settings → Secrets and variables → Actions); без него задание падает с пояснением. Запуск вручную — вкладка Actions → «Backup of the Manba database» → Run workflow.

Перед массовой загрузкой или правкой — внеочередной снимок: `SELECT take_editorial_snapshot('перед загрузкой …');`.

**Как восстановить** (делается по просьбе автора, сначала — снимок текущего состояния):

- Из снимка в базе: для каждой таблицы `INSERT INTO <таблица> OVERRIDING SYSTEM VALUE SELECT * FROM jsonb_populate_recordset(NULL::<таблица>, (SELECT tables-><'таблица'> FROM editorial_snapshots WHERE id = <номер>)) ON CONFLICT DO NOTHING;` — по порядку: стороны, термины, места, темы, затем зависимые таблицы. Журнал `change_log` только дополняется (удалять из него нельзя).
- Из копии в репозитории: новая пустая база → миграции и загрузка источников (обычный запуск сайта) → `gunzip -c editorial.sql.gz | psql "$DATABASE_URL"`.
