# Переезд базы с Supabase на Neon

Решение автора 07.11.2026. Зачем: на бесплатном Supabase база занимает 376 МБ из 500, а на бесплатном Neon — 1 ГБ на проект. Это место нужно для новых книг: шиитского тафсира, книг об отмене аятов, летописей после 302 г. х. и сочинений учёных.

Копирование делает GitHub Actions по кнопке. Пароли баз вписываются только в настройки GitHub и Render и никогда не пересылаются в чат.

## Шаги

1. **Создать проект на Neon.** Откройте neon.tech → Sign up (удобнее через GitHub) → Create project:
   - имя `manba`;
   - Postgres 17;
   - регион **AWS Europe Central 1 (Frankfurt)** — рядом с сервером Render.
2. **Скопировать строку подключения.** На странице проекта нажмите **Connect**. **Выключите** «Connection pooling» — нужна прямая строка. Скопируйте строку вида `postgresql://…@ep-….eu-central-1.aws.neon.tech/neondb?sslmode=require`. В чат её не присылайте.
3. **Вписать два секрета в GitHub.** Откройте репозиторий `d81st/manba-materials` → Settings → Secrets and variables → Actions → New repository secret:
   - `DATABASE_URL` — **текущая** строка Supabase. Её можно взять в Render: сервис `manba` → Environment → `DATABASE_URL`. Этот же секрет запускает еженедельную резервную копию: без него копия до сих пор ни разу не сделана;
   - `NEW_DATABASE_URL` — строка Neon из шага 2.
4. **Ничего не менять в админке** до конца переезда: правки, сделанные после копирования, останутся в старой базе.
5. **Запустить копирование.** В `d81st/manba-materials` откройте Actions → «Move the Manba database» → Run workflow. Через несколько минут должна появиться зелёная галочка, а в конце журнала — строка «The copies match». Если галочка красная, напишите мне, я посмотрю журнал.
6. **Переключить сайт.** Откройте Render → сервис `manba` → Environment и замените значение `DATABASE_URL` на строку Neon — ту же прямую строку. `DATABASE_SSL` оставьте `true`. После сохранения Render сам перезапустит сайт.
7. **Сказать мне** — я проверю сайт и базу.
8. **Переставить секреты: Neon — рабочая база, Supabase — запасная.** В `d81st/manba-materials` → Settings → Secrets and variables → Actions:
   - `DATABASE_URL` заменить на строку Neon — с неё теперь идёт еженедельная резервная копия;
   - добавить `STANDBY_DATABASE_URL` — строку Supabase (прежнее значение `DATABASE_URL`);
   - `NEW_DATABASE_URL` удалить.
9. **Supabase остаётся запасной базой.** Задача «Standby copy of the Manba database» по воскресеньям и средам копирует в него рабочую базу целиком. Дважды в неделю — ещё и затем, чтобы бесплатный Supabase не засыпал от бездействия. Первый раз её можно запустить вручную: Actions → Run workflow. Если запасная база окажется новее рабочей (секреты перепутаны), задача откажется её перезаписывать.

**Предел запасной базы.** Бесплатный Supabase вмещает 500 МБ. Копия разворачивается в полный объём, а не в сжатом виде: сейчас это около 370 МБ. Поэтому задача запасной копии сначала удаляет старые таблицы, а потом пишет новые — иначе на время копирования понадобилось бы вдвое больше места. Когда рабочая база перерастёт 460 МБ, задача остановится с объяснением. Дальше полная запасная база на бесплатном Supabase невозможна. Останется еженедельная резервная копия всего, что сделано руками, в `manba-materials`: тексты источников заново загружаются из репозитория. Решать тогда: платный тариф, второй бесплатный Neon как запасной или только резервная копия.

## Если Neon перестал работать

1. Render → сервис `manba` → Environment → `DATABASE_URL` вернуть на строку Supabase. Сайт перезапустится на запасной базе. В ней данные не старше последней копии: воскресенье или среда.
2. В `manba-materials` поменять секреты местами: `DATABASE_URL` — Supabase, `STANDBY_DATABASE_URL` — Neon (или удалить его, пока Neon не починят).

## Что копируется

Обе схемы: `library` — тексты источников (с миграции 049, до неё они лежали в `public`), и `public` — темы, позиции, словарь, жизнеописание, историческая линия, тесты, видео, учётные записи, журнал, снимки редакции и список применённых миграций (`docs/DATA_MODEL.md`, «Две схемы»). Поэтому сайт продолжит работу с того же места. Задача также создаёт в новой базе роли `anon` и `authenticated`, на которые закрыты таблицы, ставит расширения `ltree` и `pg_trgm` в схему `extensions` и путь поиска `public, library, extensions`.

Запасная копия перед восстановлением удаляет в Supabase все таблицы схемы `public` и схему `library` целиком: так таблица, переехавшая из одной схемы в другую, не остаётся в запасной базе вторым экземпляром.

Сценарий проверен локально на копии базы: числа совпали, миграции и загрузка источников сочли всё уже сделанным, защита опубликованных текстов от изменения перенеслась.

## Особенности Neon

- **База засыпает без запросов.** Первый запрос после паузы идёт на долю секунды дольше.
- **Нет встроенного планировщика.** Еженедельный снимок редакции делает задача резервной копии в `manba-materials`, если за последние 6 дней снимка не было.
- **Только прямая строка.** Для сайта и задач нужна строка без «Connection pooling»: запуск миграций держит блокировку на всё соединение, а в режиме пула это не работает.
