# Рабочая база Neon, запасная — Supabase

Переезд выполнен 07.11.2026 (решение автора: на бесплатном Supabase база занимала 376 МБ из 500, на бесплатном Neon — 1 ГБ на проект; место нужно для новых книг). Копию сделала задача «Move the Manba database» в `d81st/manba-materials`, числа в старой и новой базе совпали, сайт переключён на Neon. Пошаговая инструкция переезда — в истории этого файла в git.

Пароли баз вписываются только в настройки GitHub и Render и никогда не пересылаются в чат.

## Как устроено

| Что | Где |
| --- | --- |
| Рабочая база | Neon, проект `manba`, регион Frankfurt, Postgres 17. Строка — в Render (`DATABASE_URL`, прямая, без «Connection pooling») и в секрете `DATABASE_URL` репозитория `manba-materials` |
| Запасная база | Supabase `manba`. Строка — в секрете `STANDBY_DATABASE_URL` репозитория `manba-materials` |
| Еженедельная резервная копия | `manba-materials`, задача «Backup of the Manba database» — `docs/BACKUP.md` |
| Запасная копия | `manba-materials`, задача «Standby copy of the Manba database», воскресенье и среда 04:17 UTC |

**Запасная копия** копирует рабочую базу в Supabase целиком: обе схемы — `library` (тексты источников) и `public` (всё, что делается в админке, учётные записи, журнал, снимки, список миграций; `docs/DATA_MODEL.md`, «Две схемы»). Дважды в неделю — ещё и затем, чтобы бесплатный Supabase не засыпал от бездействия. Перед записью задача сама удаляет в Supabase таблицы, функции и последовательности схемы `public` и схему `library` целиком, затем восстанавливает копию и сравнивает числа. Если запасная база окажется новее рабочей (секреты перепутаны или сайт уже работает на запасной), задача откажется её перезаписывать. Запустить вручную: Actions → «Standby copy of the Manba database» → Run workflow.

**Предел запасной базы.** Бесплатный Supabase вмещает 500 МБ. Копия разворачивается в полный объём, а не в сжатом виде: сейчас это около 370 МБ. Поэтому старые таблицы удаляются до записи новых — иначе на время копирования понадобилось бы вдвое больше места. Когда рабочая база перерастёт 460 МБ, задача остановится с объяснением. Дальше полная запасная база на бесплатном Supabase невозможна; останется еженедельная резервная копия всего, что сделано руками, а тексты источников заново загружаются из репозитория. Решать тогда: платный тариф, второй бесплатный Neon как запасной или только резервная копия.

## Если Neon перестал работать

1. Render → сервис `manba` → Environment → `DATABASE_URL` заменить на строку Supabase (Session pooler, порт 5432). Сайт перезапустится на запасной базе. В ней данные не старше последней копии: воскресенье или среда.
2. В `manba-materials` поменять секреты местами: `DATABASE_URL` — Supabase, `STANDBY_DATABASE_URL` — Neon (или удалить его, пока Neon не починят).

## Особенности Neon

- **База засыпает без запросов.** Первый запрос после паузы идёт на долю секунды дольше.
- **Нет встроенного планировщика.** Еженедельный снимок редакции делает задача резервной копии в `manba-materials`, если за последние 6 дней снимка не было.
- **Только прямая строка.** Для сайта и задач нужна строка без «Connection pooling»: запуск миграций держит блокировку на всё соединение, а в режиме пула это не работает.
- **Предупреждение в логах Render** о `sslmode=require` безопасно. Убрать его: в строке заменить `sslmode=require` на `sslmode=verify-full` (в Render и в секрете `DATABASE_URL`).
