# Переезд базы с Supabase на Neon

Решение автора 07.11.2026. Зачем: на бесплатном Supabase база занимает 376 МБ из 500, а на бесплатном Neon — 1 ГБ на проект. Это место нужно для новых книг: шиитского тафсира, книг об отмене аятов, летописей после 302 г. х. и сочинений учёных.

Копирование делает GitHub Actions по кнопке. Пароли баз вписываются только в настройки GitHub и Render и никогда не пересылаются в чат.

## Шаги

1. **Создать проект на Neon.** Откройте neon.tech → Sign up (удобнее через GitHub) → Create project:
   - имя `manba`;
   - Postgres 17;
   - регион **AWS Europe Central 1 (Frankfurt)** — рядом с сервером Render.
2. **Скопировать строку подключения.** На странице проекта нажмите **Connect**. **Выключите** «Connection pooling» — нужна прямая строка. Скопируйте строку вида `postgresql://…@ep-….eu-central-1.aws.neon.tech/neondb?sslmode=require`. В чат её не присылайте.
3. **Вписать два секрета в GitHub.** Откройте репозиторий `d81st/manba-materials` → Settings → Secrets and variables → Actions → New repository secret:
   - `DATABASE_URL` — **текущая** строка Supabase. Её можно взять в Render: сервис `manba` → Environment → `DATABASE_URL`. Этот же секрет запускает еженедельную резервную копию: без него копия до сих пор ни разу не сделана;
   - `NEW_DATABASE_URL` — строка Neon из шага 2.
4. **Ничего не менять в админке** до конца переезда: правки, сделанные после копирования, останутся в старой базе.
5. **Запустить копирование.** В `d81st/manba-materials` откройте Actions → «Move the Manba database» → Run workflow. Через несколько минут должна появиться зелёная галочка, а в конце журнала — строка «The copies match». Если галочка красная, напишите мне, я посмотрю журнал.
6. **Переключить сайт.** Откройте Render → сервис `manba` → Environment и замените значение `DATABASE_URL` на строку Neon — ту же прямую строку. `DATABASE_SSL` оставьте `true`. После сохранения Render сам перезапустит сайт.
7. **Сказать мне** — я проверю сайт и базу.
8. **Обновить секрет резервной копии.** В `d81st/manba-materials` замените секрет `DATABASE_URL` на строку Neon, а `NEW_DATABASE_URL` удалите.
9. **Supabase пока не удалять.** Неделю-две он полежит как запасной. Потом проект можно поставить на паузу (Pause project).

## Что копируется

Вся схема `public`: тексты источников, темы, позиции, словарь, жизнеописание, историческая линия, тесты, видео, учётные записи, журнал, снимки редакции и список применённых миграций. Поэтому сайт продолжит работу с того же места. Задача также создаёт в новой базе роли `anon` и `authenticated`, на которые закрыты таблицы, ставит расширения `ltree` и `pg_trgm` в схему `extensions` и путь поиска `public, extensions`.

Сценарий проверен локально на копии базы: числа совпали, миграции и загрузка источников сочли всё уже сделанным, защита опубликованных текстов от изменения перенеслась.

## Особенности Neon

- **База засыпает без запросов.** Первый запрос после паузы идёт на долю секунды дольше.
- **Нет встроенного планировщика.** Еженедельный снимок редакции делает задача резервной копии в `manba-materials`, если за последние 6 дней снимка не было.
- **Только прямая строка.** Для сайта и задач нужна строка без «Connection pooling»: запуск миграций держит блокировку на всё соединение, а в режиме пула это не работает.
